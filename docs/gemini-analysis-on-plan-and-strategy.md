# Comic-Zork 프로젝트 분석 및 개선 제안 리포트

## 1. 프로젝트 배경 및 목적

### 분석 요약

* **배경**: 본 프로젝트는 역사적인 두 오픈소스 프로젝트인 'Zork I'(게임플레이 및 월드 시뮬레이션)과 'Microsoft Comic Chat'(만화 스타일 시각 표현)을 결합하여 브라우저 네이티브 환경의 만화 어드벤처로 재상상하는 실험적 시도입니다. 과거의 런타임 환경을 그대로 복제(에뮬레이션)하는 기존의 포팅 방식에서 벗어나, 레거시 소스코드에서 의미론적 구조를 추출하고 이를 WebAssembly 기반의 현대적 아키텍처로 재구현하고자 합니다.

* **목적**: 다중 AI 코딩 에이전트(Multi-agent) 환경에서 AI가 레거시 코드를 이해하고, 중간 표현(IR)을 구축하며, 브라우저 네이티브 애플리케이션으로 마이그레이션하는 선진적 워크플로우의 레퍼런스를 실증하는 것이 1차적 목적입니다. 나아가 게임 완성 자체보다 이 과정에서 도출된 기술적 자산(엔진, ZIL 임포터, IR 규격, AI 현대화 방법론)을 기반으로 컨설팅, 교육, SaaS, 상용 툴링 등의 비즈니스 기회를 창출하는 1인 기업(Solopreneur) 플랫폼 구축을 최종 지향점으로 둡니다.

### 개선할 사항 (Critique & Improvements)

* **IP(지식재산권) 및 상표권 리스크 관리 로드맵 부재**: 프로젝트의 본질이 '상업적 자산화 및 컨설팅 신뢰도 확보'에 있다면, 'Zork' 및 'Microsoft Comic Chat'이라는 브랜드 자산과 소스코드의 라이선스(MIT) 범위 외의 상표권 침해 소지를 초기에 격리해야 합니다. Phase 4~5로 이행하기 전, 엔진과 중간 표현(IR)의 독자적인 브랜드명(Generic Branding)을 확립하고, 레거시 소스코드는 플러그인 형태로 완전히 분리하여 상용화 시 법적 리스크를 차단하는 구조 설계가 필요합니다.

* **시장 소구력(Target Audience)의 정렬**: 타깃 오디언스를 개발자 경험(DX) 팀, 소프트웨어 아키텍트, AI 엔지니어링 팀으로 설정했으나, 고전 게임 현대화 사례만으로는 일반적인 엔터프라이즈 레거시(예: Cobol, 레거시 Java/C++) 현대화 수요를 흡수하기에 간극이 느껴질 수 있습니다. 프로젝트의 목적을 달성하기 위해, ZIL 분석 과정을 단순 게임 분석이 아닌 "도메인 특화 언어(DSL)의 최신 아키텍처 전환 사례"로 프레임포지셔닝하고, 엔터프라이즈 비즈니스 로직 추출과의 공통 분모를 문서(OpenWiki)에 적극적으로 남겨야 합니다.

## 2. 수행 전략

### 분석 요약

* **전략**: 단순 소스 대 소스(Source-to-Source) 컴파일을 배제하고, 고전 런타임(Z-Machine)을 재만들지 않는 '의미론적 보존(Semantic Preservation)' 전략을 취합니다. ZIL(Zork Implementation Language) 코드를 분석하여 방(ROOM), 오브젝트(OBJECT), 액션(ACTION) 등의 개념을 플랫폼 독립적인 중간 표현(IR)으로 추출하고, Comic-Zork 엔진이 이 IR을 인터프리팅하거나 실행하도록 만듭니다.

* **아키텍처 전략**: 기존의 터미널 텍스트 출력 방식을 구조화된 '게임플레이 이벤트 스트림'으로 전환하여 시각 표현 레이어(만화 패널, 말풍선, 캐릭터 레이아웃)와 게임 엔진 로직을 완전히 격리하는 이벤트 구동형(Event-Driven) 브라우저 런타임을 구축합니다.

### 개선할 사항 (Critique & Improvements)

* **C++ 레거시(Comic Chat)와 웹 프론트엔드 간의 아키텍처 경계 모호성**: Comic Chat은 C++ 기반 애플리케이션이며 presentation 개념을 제공합니다. 이를 브라우저 네이티브로 마이그레이션할 때, Comic Chat의 레이아웃 알고리즘까지 WASM으로 컴파일할 것인지, 아니면 UI 렌더링 레이어는 현대적인 웹 기술(TypeScript/Canvas/WebGL)로 전면 재작성할 것인지에 대한 아키텍처 경계가 명확하지 않습니다. 플랫폼 독립적인 IR 및 이벤트를 지향하는 만큼, 렌더링/애니메이션 영역은 WASM 내부가 아닌 브라우저 네이티브 웹 컴포넌트 레이어로 완전히 일임하고, WASM 엔진은 오직 순수 상태(State)와 이벤트 시퀀싱만 담당하도록 인터페이스 규격을 선제적으로 엄격화해야 합니다.

* **이벤트 구동 아키텍처의 상태 동기화 비용**: 텍스트 출력을 만화 패널 및 말풍선 시각화 이벤트로 전환할 때, 연속적인 사용자 입력에 따른 상태 변화(State Mutation)가 UI 레이아웃의 병목을 유발할 수 있습니다. 브라우저 런타임의 영속성(Persistence) 및 입력 처리 계층 간의 비동기 이벤트 큐(Queue) 설계가 전략 문서(v2)에 구체화되어야 안정적인 다중 패널 렌더링이 가능해집니다.

## 3. 방법론 및 워크플로우

### 분석 요약

* **방법론**: AI 에이전트의 효율적 협업을 위해 지식을 구조적 지식(Structural Knowledge - Graphify)과 의미론적 지식(Semantic Knowledge - OpenWiki)으로 엄격히 이원화하여 관리합니다.

* **파이프라인**: ZIL 언어의 특성상 하위 도구들이 이를 직접 파싱할 수 없으므로, LLM의 추론 능력을 이용해 1차 의미론적 분석(Semantic Analysis)을 수행하고, 이를 통해 정형화된 IR을 생성한 뒤 Graphify(AST 기반 구조 분석)와 OpenWiki(설계 의도 및 비헤이비어 문서화)에 입력하는 단계적 워크플로우를 가집니다. AI 에이전트는 코드 변경 시 반드시 문서와 Graphify 아티팩트를 갱신하는 제약을 따릅니다.

### 개선할 사항 (Critique & Improvements)

* **ZIL 분석 단계에서 LLM 의존도 과다로 인한 비결정성(Hallucination) 위험**: 현재 평가된 어떤 도구도 ZIL의 네이티브 파싱을 지원하지 않아, LLM이 직접 ZIL 의미론을 분석하도록 제안되었습니다. 그러나 ZIL은 단순 데이터 선언 외에도 `ROUTINE`이나 복잡한 퍼즐 로직 등 명령형(Imperative) 스크립트 요소를 포함합니다. LLM의 생(Raw) 프롬프트에만 의존해 이를 IR로 변환할 경우, 조건문 누락이나 상태 전이 오류 같은 비결정적 에러가 발생할 확률이 높습니다.

* **개선 제안**: 완전한 AI 자동화 이전에, ZIL 문법의 최소 구조(S-Expression 기반 렉서/파서)를 파싱할 수 있는 가벼운 Tree-sitter 문법 정의서 또는 ANTLR 기반 프리파서(Pre-parser)를 방법론 초기 단계에 도입해야 합니다. 이를 통해 추상 구문 트리(AST)를 1차 확보한 뒤 AI 에이전트에 컨텍스트로 제공한다면, 변환의 신뢰도가 극대화되며 이 프리파서 자체도 훌륭한 독자 자산(ZIL Semantic Importer)이 될 수 있습니다.

* **에이전트 워크플로우의 'Graphify 갱신 루프' 병목**: 에이전트가 변경 사항을 적용할 때마다 Graphify 아티팩트를 재생성하도록 명시되어 있습니다. 대규모 리포지토리로 확장될 경우 그래프 전처리 오버헤드가 발생할 수 있으므로, CI/CD 파이프라인 또는 Git Hook 연동을 통해 그래프 재생성을 자동화하고, 에이전트는 코드와 OpenWiki(개념적 문서) 수정에만 집중할 수 있도록 에이전트의 책임 범위를 가볍게 유지하는 것이 생산성 측면에서 유리합니다.

## 종합 제언

Comic-Zork는 1인 비즈니스의 지속 가능한 지식 자산을 만들기 위한 훌륭한 아키텍처적 비전과 영리한 지식 분리 전략을 갖추고 있습니다. 본 프로젝트가 단순 토이 프로젝트를 넘어 상용 수준의 마이그레이션 툴킷 자산으로 인정받기 위해서는 다음의 세 가지만 명확히 고도화하면 됩니다.

1. **ZIL 프리파서 도입**: 에이전트의 추론 에러를 줄이기 위한 결정적(Deterministic) 구문 분석 계층 도입.
2. **인터페이스 중심 설계**: WASM 내부 게임 엔진과 외부 웹 UI 간의 직렬화(Serialization) 규격 선제 정의.
3. **브랜드 분리**: 레거시 IP 리스크를 회피하고 상용화 전환이 용이하도록 코어 엔진과 IR의 독자 브랜드화 추진.
